# SmartCare 터미널 MVP

## 웹 상담과 A/S 예약

완료된 상담에는 **고객용 AI 리포트**가 표시됩니다. 같은 상담을 **내 상담**에서 다시 열면 최신 저장 내용으로 요약을 확인할 수 있습니다. 고객용 리포트는 모델·코드, 증상, 자가조치 결과, 희망 방문 일정, 접수 시각과 상담 번호를 표시합니다.

후속 기사 사이트는 동일한 상담 ID와 저장소를 사용하도록 설계합니다. `backend/reports.py`의 `technician_report`는 고객용 요약과 함께 점검·대화·동일 기기 이력, 첨부 메타데이터와 A/S 신청 정보를 구성합니다. 기사 사이트에서 호출할 API에는 로그인과 상담 접근 권한 검사가 필요합니다. 현재 고객 API는 고객용 리포트만 반환합니다.

프로젝트 루트에서 `.\.venv\Scripts\python.exe backend/web_app.py`를 실행한 다음 브라우저에서 `http://127.0.0.1:8765`를 엽니다. 기본 화면은 **상담**입니다. 제품 유형을 선택하고, **내 기기**에 등록한 기기를 고르면 모델명이 자동으로 적용됩니다. 등록하지 않은 기기는 챗봇에서 모델명을 확인합니다. 에어컨·건조기·기타 가전은 증상 기록과 A/S 연결 흐름을 지원합니다.

**내 상담**에서는 착수 시각, 최근 기록 시각, 상태를 확인할 수 있습니다. 진행 중인 상담은 저장된 단계에서 이어가고, 해결된 상담의 **문제가 다시 발생했어요**를 누르면 이전 상담을 보존하면서 연결된 재발 상담을 시작합니다. 새 상담에서 같은 등록 기기를 선택해도 기존 상담과 연결됩니다. 상담 JSON의 `device_history`에는 이전 상담의 날짜, 상태, 증상과 자가조치 결과를 담습니다. 등록 기기와 내 상담 목록은 같은 브라우저 프로필을 기준으로 하며, 브라우저 식별 정보 없이 저장한 이전 상담은 자동으로 목록에 합치지 않습니다.

에러 선택지에는 등록된 4개 PDF의 표시 메시지 표에 있는 코드와 알림을 표시합니다. 코드가 확인되면 관련 매뉴얼의 점검과 조치부터 진행하고, 해결되지 않거나 적용할 조치가 없을 때 상세 증상을 기록합니다. 코드가 없거나 확인하기 어려우면 상세 증상을 먼저 입력하고, 입력 내용에서 대응되는 매뉴얼 점검 항목을 찾습니다. 상담 질문은 선택지와 **직접 입력**을 함께 제공합니다.

자가조치로 해결되지 않거나 적용할 조치가 없으면 사진·영상·녹음 첨부 화면이 나타납니다. 기존 파일을 선택하거나 브라우저에서 촬영·녹음할 수 있습니다. 자료가 없어도 다음으로 넘어갈 수 있습니다. A/S 연결에 동의하면 희망 방문 날짜와 시간을 입력하고 접수 신청을 완료할 수 있습니다.

브라우저에서 직접 촬영·녹화하려면 카메라 또는 마이크와 해당 권한이 필요합니다. 스마트폰에서 사용할 때는 HTTPS 주소로 접속합니다. HTTPS 역방향 프록시로 배포할 경우 서버 프로세스에 `SMARTCARE_PUBLIC_ORIGIN=https://서비스-도메인`을 설정하고 프록시가 원래 `Host` 헤더를 전달하도록 구성합니다.

상담 JSON에는 `service_detail`, `attachments`, `service_request`가 들어갑니다. 첨부의 `path`는 상담 저장 폴더 기준 상대 경로이며, 파일은 `database/cases/media/` 아래에 보관합니다. A/S 신청에는 희망 일정, 신청 시각, 선택 입력한 연락처, 기사 연동 상태가 남습니다. 현재 기사에게 일정이 전달되거나 방문이 확정되지 않으며, 후속 기사 배정·연락 시스템과 리포트가 이 기록을 사용할 수 있습니다.

프로젝트 루트에서 PowerShell로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

## 실제 매뉴얼 검색

```powershell
.\.venv\Scripts\python.exe backend/cli.py local
.\.venv\Scripts\python.exe backend/cli.py local --model TR14WK1 --error OE
```

기본 입력 자료는 `데이터/세탁기 매뉴얼/manuals.zip`입니다. ZIP에 들어 있는 PDF를 메모리에서 읽고, 입력한 모델의 OE 항목과 PDF 뷰어 페이지를 출력합니다. 다른 위치의 ZIP은 `--archive`로 지정할 수 있습니다.

| 모델 | 문서 번호 | PDF 페이지 |
|---|---|---|
| T25OZ0 | MFL71831239 | 45, 46 |
| TR14WK1 | MFL71831208 | 36, 37 |
| TR13ML2 | MFL71831210 | 39, 40 |
| TR16DV6 | MFL71831233 | 35, 36 |

검색 대상은 `backend/manual_search.py`의 모델별 문서 목록에서 관리합니다. 새 문서는 적용 모델과 문서 번호를 확인한 뒤 목록에 추가하고, 실제 오류 항목과 출력 페이지를 대조합니다. 현재 추출 규칙은 선정된 네 PDF의 OE 표를 기준으로 합니다.

## OpenAI 답변 시연

```powershell
Copy-Item .env.example .env
# .env를 열어 OPENAI_API_KEY에 본인의 키를 입력합니다.
.\.venv\Scripts\python.exe backend/cli.py openai-demo
```

이미 `.env`가 있으면 복사 명령을 건너뜁니다. 이 명령은 가상 증상과 가상 매뉴얼 근거를 OpenAI에 보내고 예시 출처와 응답을 표시합니다. API 모델은 `OPENAI_MODEL`로 설정합니다. 모델 호출은 `backend/llm.py`에서 관리합니다.

## 대화형 로컬 상담

```powershell
.\.venv\Scripts\python.exe backend/cli.py chat
```

예를 들어 `OE 에러가 떠요` → `TR14WK1이에요`라고 입력하면 PDF 36쪽을 근거로 배수 호스가 올려져 있는지 질문합니다. `네`라고 답하면 해당 조치를 안내합니다. `아니요`라고 답하면 PDF 37쪽의 다음 점검 질문으로 넘어갑니다. 점검 또는 조치가 어렵거나 적절한 조치가 남아 있지 않으면 A/S 연결 의사를 묻고 답을 저장합니다. 현재 연결 요청은 상담 기록에 남으며 실제 접수에는 팀의 A/S 시스템 연동이 필요합니다.

현재 안내 범위는 위 4개 모델의 OE 배수 오류와 검토한 호스 증상입니다. 조치마다 적용 조건, 설명서 문서 번호, PDF 페이지, 원문 발췌를 표시합니다. 확인된 안전 위험 문구나 근거 부족, 조치 소진 시 전문 A/S를 권장합니다.

상담은 기본값으로 `database/cases/<case_id>.json`에 매 응답마다 저장됩니다. 파일에는 모델명, 고객 증상, 코드, 조치별 수행 여부·결과·출처, 상담 상태와 전체 대화가 들어갑니다. `performed: null`은 수행 여부가 확인되지 않은 상태입니다. A/S 및 리포트 Agent는 버전이 표시된 이 JSON을 입력으로 사용할 수 있으며, 현재 실행은 새 사건을 시작합니다. 기본 상담 저장 경로는 Git에서 제외됩니다.

## 가상 대화 시연과 테스트

```powershell
.\.venv\Scripts\python.exe backend/cli.py openai-demo --interactive
.\.venv\Scripts\python.exe -m unittest discover -s backend -v
```

`openai-demo`는 API 연결을 확인하기 위한 개발자용 명령입니다. 실제 자가조치 상담은 `chat` 명령에서 시작합니다. 실제 상담은 로컬 규칙과 매뉴얼 검색만 사용합니다. OpenAI 요청에는 미리 정의된 가상 시연 단계와 예시 자료만 들어갑니다.
